0. 먼저 물어볼 것 (한 번만, 한 번에)

작업을 시작하면 위 '기본 정보'와 기존 사이트(있다면)를 먼저 확인한다. 그 뒤 아래 기준으로 꼭 필요한 질문만 골라 한 번에 묻는다.

물어보는 것: 내가 답하지 않으면 결과가 크게 틀어지고, 네가 조사나 추측으로 알 수 없는 것만.
• 업종·목표·주요 고객이 비어 있고 기존 사이트로도 알 수 없을 때
• 무드 방향: 업종을 보고 서로 다른 무드 3~4개를 한 줄씩 제안하고 고르게 한다(예: '따뜻한 동네 빵집 / 정갈한 일본식 / 대담한 편집 디자인'). 내가 이미 적었으면 묻지 않는다.
• 가격·연락처·실적처럼 사실이어야 하는 정보가 없을 때
• 이미지·영상 생성에 돈이 드는데 예산이 비어 있을 때
• 언어가 비어 있고 고객으로 보아 영어 등이 필요해 보일 때

물어보지 않는 것: 색 값, 글꼴, 레이아웃, 기술 구성, 애니메이션, 파일 구조, 섹션 순서처럼 디자이너·개발자가 스스로 판단할 일. 이건 네가 정하고 이유만 기록한다.

질문 방식:
• 질문은 최대 6개. 객관식 보기와 네 추천안(추천 표시)을 함께 준다.
• "모르겠음"이라고 답하면 추천안으로 진행한다.
• 답을 받은 뒤에는 같은 것을 다시 묻지 않는다. 막히는 게 생겨도 할 수 있는 작업을 먼저 끝낸 뒤 짧게 묻는다.

진행 규칙
• 1단계는 히어로(첫 화면) 시안 3~5개를 실제 이미지로 만들어 보여 주는 데까지만 한다.
• 내가 번호를 고르고 "제작해"라고 해야 전체 사이트를 만든다. "3번이 좋다"는 선택만 저장하고 기다린다. "3번으로 제작해"는 선택과 승인을 함께 뜻한다. 네가 임의로 고르지 않는다.
• 시안 수정은 시안 단계에서 처리한다. 이미 승인한 일을 다시 묻지 않는다.
• 세션이 끊겨도 이어 갈 수 있게, 프로젝트 안에 다음 파일을 만들고 단계마다 갱신한다.
  - CLAUDE.md: 새 세션이 가장 먼저 읽을 규칙. "HANDOFF.md → docs/DESIGN_SYSTEM.md 순서로 읽고 '남은 일'을 이어서 진행"
  - HANDOFF.md: 지금 어디까지 했는지, 내 피드백과 처리 결과(몇 차인지), 남은 일
  - docs/CONTENT.md: 확정된 원문 목록과 출처
  - docs/DESIGN_SYSTEM.md: 색·글꼴·크기·간격·버튼·모션 규칙과 그렇게 정한 이유
• git 저장소로 관리하고 단계마다 커밋한다. 비밀값(API 키 등)은 .env.local 등 git에서 제외된 곳에만 두고, 출력하거나 커밋하지 않는다.

품질 기준 (업종이 달라도 이 수준 아래면 보여 주지 않는다)

기준점: 업종 최고 브랜드의 사이트, 그리고 awwwards 수상작 옆에 나란히 놓아도 밀리지 않는 수준. "동네 가게니까 이 정도면 됐다"는 없다. 업종이 바뀌어도 무드만 바뀌고 완성도는 그대로다.

이 수준은 다음에서 나온다. 모두 지킨다.
• 시그니처 아이디어 하나: 이 브랜드에서만 성립하는 시각·모션 아이디어를 하나 정하고 사이트 전체를 꿰뚫게 한다(예: 빵집이면 반죽이 부푸는 속도로 글자가 올라옴, 법률사무소면 조문처럼 정렬되는 편집 그리드). 다른 업종에 그대로 옮겨 붙일 수 있는 효과면 다시 만든다.
• 서체는 실측으로 고른다: 후보 6~10개를 실제 헤드라인·본문 문장, 실제 크기로 나란히 렌더해 비교 보드를 만들고, 고른 이유를 기록한다. 제목·본문·숫자(가격) 역할을 나누고, 필요하면 한글과 영문·숫자를 다른 서체로 짝짓는다.
• 색은 적게, 의도 있게: 바탕 2~3가지와 글자색 정도로 시작하고, 어두운 섹션과 밝은 섹션을 번갈아 긴 페이지에 호흡을 준다. 강조색은 이유가 있을 때만.
• 사진·영상이 주인공일 때는 크게, 자르지 않고, 틀로 작게 만들지 않는다. 실제 자료가 약하면 생성 이미지보다 조판과 그래픽으로 해결하는 쪽을 먼저 검토한다.
• 세부까지 설계: 버튼의 마우스 반응, 숫자 정렬, 가격 표기(기호는 작게·숫자는 크게), 입력칸이 입력칸으로 보이는지, 로고 등장, 섹션 머리말 형식까지 하나의 규칙으로 맞춘다.
• 한글 조판이 완벽: 고아줄·어색한 줄바꿈·한 글자 줄이 한 곳도 없게. 문장부호 표기 규칙(줄표·별표 등 쓸지 말지)을 정해 지킨다.

스스로 먼저 비판한다: 나에게 보여 주기 전에 매번 실제 화면을 캡처해 보고 아래 질문에 답한다. 하나라도 '예'면 고친 뒤에 보여 준다.
1) 업종 이름만 바꾸면 다른 회사 사이트로 써도 되는가?
2) 템플릿이나 AI 생성 사이트에서 본 것 같은 구성·효과가 있는가?
3) 만들다 만 것처럼 어설픈 효과, 이유 없이 들어간 장식이 있는가?
4) 모바일 390px에서 어색하게 끊기거나 작아 보이는 곳이 있는가?
5) 가장 공들인 섹션과 가장 덜 공들인 섹션의 완성도 차이가 눈에 띄는가?
자기 평가 결과는 짧게 기록하고, 고친 내용도 함께 알려 준다.

1. 콘텐츠 모으기

기존 사이트가 있으면 문구, 사업 정보, 가격, 서비스 조건, 연락처, 링크, 실제 포트폴리오, 로고 원본만 가져온다. 기존 디자인(색·글꼴·배치·효과)은 참고하지 않는다. 첫 화면만 보고 끝내지 말고 내부 페이지, 스크롤 후 나오는 내용, FAQ, 팝업, 언어별 페이지까지 확인한다.

모은 원문은 docs/CONTENT.md에 출처와 함께 고정한다. 배치와 줄바꿈은 바꿔도 되지만, 문구를 임의로 고쳐 쓰거나 줄이거나 빼지 않는다. 가격, 기간, 실적 숫자, 서비스 범위는 추측으로 채우지 않는다. 기존 사이트가 없거나 문구가 부족하면 초안을 써서 "새로 쓴 문구"로 표시하고 확인을 받는다.

로고는 원본 비율을 지킨다. 없으면 브랜드 이름을 글자로 임시 표시하고 알린다. 실제 고객 작업물·후기는 원본만 쓰고, AI로 만든 가상 작업물을 실제 실적처럼 보이게 하지 않는다.

2. 레퍼런스 먼저 보기

"고급스럽게, 감각적으로" 같은 형용사만으로 디자인하지 않는다. 이 업종과 무드에 맞는 실제 레퍼런스를 조사한다.
• 출발점: awwwards.com, siteinspire.com, savee.com, cosmos.so, are.na, the-brandidentity.com, pinterest.com, 그리고 같은 업종에서 디자인이 뛰어난 국내외 브랜드 사이트
• 12~20개를 골라 개별 작품 주소, 만든 곳, 참고할 점(구도, 글자 비례, 사진 크롭, 재료감, 움직임의 범위 등)을 기록한다.
• 로그인이나 유료로 막힌 자료는 봤다고 하지 않는다. 한 사이트를 그대로 베끼지 않는다.

내가 말하는 고감도:
• 이 브랜드를 위해 일부러 고른 글꼴, 구도, 색, 재료감
• 기억에 남는 시각 아이디어 하나, 정교한 비례·여백·크롭
• 첫 화면에서 무슨 업종인지, 무엇을 해 주는지 바로 이해됨
• 한국어 문구가 아름답고 편하게 읽히는 조판
• 시선을 이끄는 절제된 움직임
• 첫 화면부터 문의까지 끊기지 않는 완성도

AI 티가 나는 기본값 금지: 보라·네온 그라데이션, 의미 없는 크롬 구, 빛나는 구슬, 반복되는 둥근 카드, 유리 패널, 반짝이 아이콘 나열, 알약 모양 버튼 남발, 반짝이는 KPI 숫자, 의미 없는 좌표·배지·영어 장식 문구, 허술한 3D. 검정 배경에 거대한 글자만으로 고급스러움을 해결하지 않는다.

3. 히어로 시안 3~5개

배경색만 바꾼 변형이 아니라 서로 다른 방향이어야 한다. 구도, 글꼴의 성격, 시각적 중심, 소재, 밝기가 충분히 달라야 한다. 내가 고른 무드 안에서 변주하되, 최소 한 안은 예상 밖의 방향으로 만든다.

• 실제 홈페이지 첫 화면처럼 보이게 만든다(1920×1080). 로고나 브랜드 이름, 실제 헤드라인, 설명, 버튼을 넣는다. 모든 시안의 문구는 같게 해서 공정하게 비교한다.
• 무드보드, 와이어프레임, 노트북 목업으로 대신하지 않는다.
• 이미지 생성 도구(Higgsfield 등)가 연결돼 있고 예산이 있으면 아트워크를 생성한다. 생성 모델은 한글을 정확히 쓰지 못하므로 글자·버튼은 HTML/CSS로 정확히 조판해 합성한 뒤 캡처한다. 예산이 0이면 실제 사진·자료와 조판, 그래픽만으로 만든다.
• 생성 작업은 작업 ID를 기록하고 결과 파일을 프로젝트에 내려받는다. 시간 초과만 보고 같은 유료 생성을 다시 보내지 않는다. 예산을 넘지 않고, 사용 비용을 기록한다.
• 보여 주기 전에 직접 열어 오탈자, 깨진 글자, 어색한 질감, 버튼 가독성을 확인한다.
• 결과물: 번호 붙은 시안 이미지, 한눈에 비교하는 보드 1장, 크게 볼 수 있는 미리보기. 각 안의 이름, 차별점, 모바일에서의 배치, 움직임 계획, 참고한 레퍼런스를 짧게 설명한다.

보여 준 뒤 "번호를 고르고 '제작해'라고 하면 그 방향으로 전체 사이트를 만듭니다"라고 안내하고 멈춘다.

4. "제작해" 이후: 전체 사이트

고른 시안의 디자인 규칙부터 docs/DESIGN_SYSTEM.md에 정리한다.
• 색: 적은 수의 토큰(CSS :root 변수). 강조는 색보다 크기·굵기·여백으로.
• 글꼴: 웹 사용 권한이 확인된 것만. 한글은 실제 문장으로 후보를 나란히 비교해 고른다. 흔한 기본 글꼴을 습관처럼 쓰지 않는다. 필요한 글자만 묶어 직접 호스팅한다(woff2).
• 글자 크기: 화면 폭에 따라 clamp. 본문은 모바일에서도 16px 아래로 줄이지 않는다.
• 한글 줄바꿈: word-break: keep-all, 제목은 text-wrap: balance, 본문은 pretty. 한 글자 낱말이나 '·'가 줄 끝·첫머리에 혼자 남지 않게, 구절 단위로 넘기게 한다. 1440·390 폭에서 모든 섹션의 줄바꿈을 직접 본다.
• 버튼: 이 사이트만의 모양과 마우스 반응을 설계한다(HTML/CSS로 구현, 이미지로 굽지 않음).
• 모션: 한 화면에 강한 움직임은 하나만. 사이트를 대표하는 큰 효과 1~2곳, 나머지는 섬세한 작은 반응. 강제 스크롤, 긴 고정 구간, 번쩍임, 진입을 막는 긴 로딩 화면은 쓰지 않는다. prefers-reduced-motion이면 움직임을 끄고도 완성돼 보여야 한다.

모든 원문을 새 디자인에 배치한다. 순서는 읽기 쉽게 바꿔도 되지만 빼지 않는다. 없는 서비스·실적·고객을 만들지 않는다. 모든 섹션을 같은 카드 묶음으로 반복하지 않는다.

히어로 영상이 필요하고 예산이 있으면 아트워크만 영상으로 만들고 글자·버튼은 HTML로 분리한다. 소리 없는 자연스러운 반복을 목표로 하고, 시작·중간·끝 프레임과 반복 이음매를 직접 확인한다. 실패한 영상을 정지 이미지로 바꿔 놓고 완료라고 하지 않는다.

기술 구성은 유지보수가 쉬운 가벼운 쪽으로 직접 정한다(예: Vite + TypeScript 정적 사이트, 필요할 때만 서버). 최신이라는 이유로 라이브러리를 늘리지 않는다.

문의는 실제로 동작해야 한다. 보내지 않았는데 성공했다고 보여 주는 가짜 기능을 만들지 않는다. 시험 중에 실제 고객에게 메일·메시지를 보내지 않는다.

5. 검증

코드를 썼다고 끝내지 않는다.
• 빌드와 타입 검사를 통과시킨다.
• PC 1920·1440, 태블릿, 모바일 390·360에서 화면을 캡처해 직접 보고 고친다. 가로 넘침, 줄바꿈, 잘린 글자·사진, 레이아웃 흔들림을 확인한다.
• 키보드 이동, 포커스 표시, 글자 대비, 폼 이름표·오류 상태를 확인한다(axe 등 접근성 검사 0건 목표).
• 히어로 포스터와 핵심 글이 먼저 보이고, 영상·아래쪽 자료는 필요할 때 불러오게 한다.
• 제목·설명·OG 이미지·사이트맵 등 검색 노출 기본을 갖춘다.
• 원문 목록과 실제 화면을 대조해 빠진 문구가 없는지 확인하는 자동 점검 스크립트를 만든다. 금지한 표현이나 버릇이 다시 들어오지 않았는지도 이 스크립트로 검사한다.
• 고른 시안과 실제 구현을 나란히 놓고 비교한다.
• 측정하지 않은 성능 수치를 보고하지 않는다.

6. 피드백 반영

내가 "허접하다, 어색하다, AI 티 난다"고 하면 땜질하지 말고 그 부분을 새로 설계한다. 피드백마다 몇 차인지, 무엇을 왜 바꿨는지를 HANDOFF.md와 DESIGN_SYSTEM.md에 남겨 같은 실수를 반복하지 않는다. 고칠 때마다 미리보기로 실제 화면을 보여 준다.

7. 전달

• 실행 가능한 전체 소스와 잠금 파일, 짧은 README(실행·빌드 방법, 필요한 환경 변수 이름)
• 최종 이미지·영상·글꼴 자료, 원문 목록, 레퍼런스, 디자인 규칙, 생성 기록과 비용
• 검증 결과와 아직 남은 문제를 솔직하게

실제 도메인 연결과 공개 배포는 내가 따로 요청할 때 한다. "제작해" 이후에는 불필요한 중간 확인 없이 구현과 검증까지 끝낸다. 못 끝낸 부분은 완료로 포장하지 않는다.

지금 바로 0단계(필요한 질문)부터 시작하라. 답을 받으면 1~3단계를 진행해 히어로 시안을 실제로 보여 주고, 내가 고르고 "제작해"라고 할 때까지 기다려라.
