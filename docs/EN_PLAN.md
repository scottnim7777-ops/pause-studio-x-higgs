# 영어판 기획 (한국어 ↔ English 전환)

작성 2026-10-14. 구현은 다른 세션(Sonnet)이 이 문서대로 진행한다. 바꾸기 전에 이 문서와 HANDOFF.md를 먼저 읽을 것.

## 0. 목표와 원칙
- 영어를 쓰는 고객(특히 미국)도 같은 사이트를 **같은 글꼴 느낌·같은 효과**로 본다.
- **기본은 한국어.** 국기 버튼으로 한국어 ↔ 영어를 오간다.
- "누락 없이": 화면 글, 버튼, 상담 창, 오류 문구, 대체 텍스트(alt·aria), 검색엔진 정보, 미리보기 문구, 상담 메일까지 전부 영어로 나와야 한다.
- 번역은 직역하지 않는다. 미국 소상공인이 읽기 자연스러운 영어로, 지금 사이트의 말투(짧고 단정, 과장 없음)를 지킨다.

## 1. 구조: 주소를 나눈다 (`/` 한국어, `/en` 영어)
화면에서 글자만 갈아 끼우는 방식 대신, **영어 페이지를 따로 미리 만들어 둔다.**
- 이유
  1. **미국 검색**: 구글은 주소 하나에 언어 하나로 색인한다. `/en`이 따로 있어야 영어 검색에 걸린다(hreflang으로 서로 연결).
  2. **깜빡임 없음**: JS로 글자를 바꾸면 한국어가 먼저 보였다가 바뀌고, 줄 길이가 달라 효과가 어긋난다. 미리 만든 페이지는 처음부터 맞게 나온다.
  3. **공유**: 미국 고객에게 `pause8studio.com/en` 링크를 그대로 보낼 수 있다. 카톡·문자 미리보기도 영어로 나온다.
- 국기 버튼은 `/` ↔ `/en` 링크. **지금 보던 섹션을 유지**한다(두 페이지의 섹션 id가 같으므로, 스크롤할 때 버튼 링크 끝을 `#pricing`처럼 현재 섹션으로 바꿔 둠).
- 자동으로 영어로 보내지 않는다(기본 한국어). 선택은 저장하지 않는다(필요하면 나중에).

## 2. 국기 버튼 디자인·배치
**국기는 이모지가 아니라 직접 그린 작은 SVG.** 윈도우 크롬은 국기 이모지를 "KR"·"US" 글자로 보여 준다.

### 모양: 두 칸짜리 알약형 전환기
```
 ┌─────────────────────┐
 │ ◐ KO  │  ◑ EN       │   ← 높이 30px, 1px 크림 선(--cream-line), 모서리 둥근 알약
 └──▔▔▔──┴─────────────┘   ← 지금 언어 아래에만 크림색 1px 밑줄(머리줄 메뉴의 '지금 보는 장' 밑줄과 같은 말투)
```
- 국기: 지름 14px 원. 지금 언어는 **원래 색**, 다른 언어는 **흑백 + 투명도 .45**. 마우스를 올리면 색이 천천히 돌아옴(.35s).
- 글자: `KO` / `EN`, PS Display(Archivo 좁은 폭), 12px, 자간 .14em. 지금 언어는 크림, 다른 언어는 --cream-3.
- 밑줄은 바꿀 때 옆 칸으로 미끄러진 뒤 페이지가 넘어감(.3s, 동작 줄이기면 없음).
- 영어 국기: **미국 국기**를 권장(영어 고객의 주 시장이 미국). 뉴질랜드 고객도 영어 버튼은 바로 알아봄.
- 접근성: `<nav aria-label="Language">` 안에 링크 2개, 지금 언어는 `aria-current="true"`, 각 링크에 `lang`·`hreflang` 속성. 화면 읽기용 이름 "한국어" / "English".

### 자리
| 화면 | 자리 | 모양 |
|---|---|---|
| PC 머리줄 | 메뉴 링크와 [문의하기] 사이 | 두 칸 알약 |
| 휴대폰 머리줄 | 메뉴(☰) 버튼 왼쪽 | **다른 언어 한 칸만**(한국어 화면이면 `🇺🇸 EN`) — 머리줄이 붐비지 않게 |
| 휴대폰 메뉴 펼침 | 메뉴 목록 아래, 상담 버튼 위 | 두 칸 알약(크게, 높이 40px) |
| 푸터 | Menu 칸 맨 아래 | `한국어 · English` 글자 링크(국기 포함, 작게) |

머리줄이 내려갈 때 숨는 동작, 밝은 섹션 위 색 바뀜 등은 기존 머리줄 규칙을 그대로 따른다.

## 3. 문구 파일
- `src/content/ko.ts` 옆에 `src/content/en.ts`를 만든다. **같은 모양(타입)을 강제**한다.
  - `ko.ts`에서 `export type Content = typeof ko`를 만들고, `en.ts`는 `export const en: Content = {...}`로 둔다. 빠진 항목이 있으면 빌드(타입 검사)가 실패하므로 누락이 생길 수 없다.
  - 지금처럼 `export const meta`, `hero` 등을 따로 내보내는 방식이면 `ko.ts` 끝에 `export const ko = { contact, meta, nav, … }`를 묶어 내보낸다.
- `page.ts`는 `import * as C from '../content/ko'` 대신 **`renderHead(C)`, `renderBody(C)`처럼 문구를 인자로** 받게 바꾼다.
- **스크립트 안의 한국어도 문구 파일로 옮긴다.** 지금 흩어져 있는 것:
  - `ui.ts`: '메뉴'·'메뉴 닫기', '영상 재생'·'영상 일시정지', 계산기 '년', '금액 입력', '고쳐 넣을 수 있는 칸', 번호 복사 안내 등
  - `consult.ts`: 요약 '상담 종류', 복사·메일 본문의 '보낸 곳', 오류 문구(이미 `consult`에 있음)
  - `page.ts`: 머리줄·푸터의 '카카오톡 오픈채팅', '진행 단계', '샘플 광고', '질문 분류' 등 aria 문구와 대체 텍스트
  - 방법: 페이지에 `<script type="application/json" id="ui-text">`로 그 페이지 언어의 짧은 문구 묶음을 넣고, 스크립트는 거기서 읽는다(스크립트 파일은 하나로 유지).
- 확인 방법: `/en` 페이지의 **화면 글·alt·aria-label·placeholder·title·JSON-LD에 한글이 하나도 없는지** 시험(언어 버튼의 '한국어' 이름만 예외).

## 4. 한국어에 묶인 효과 → 영어판 짝
효과는 그대로 두고, **효과가 붙는 단어만 영어에서 같은 의미의 자리**로 옮긴다. 지금 `page.ts`가 `replace('관리비는', …)`처럼 한국어 단어를 찾아 효과를 씌우므로, 문구 파일에 **효과 붙일 단어를 따로 적는 칸**을 만든다(예: `pricing.cutWord: '관리비'` / `'monthly fees'`).

| 자리 | 한국어 | 영어(초안, 사용자 확인) | 효과 처리 |
|---|---|---|---|
| 히어로 제목 | 선택받는 브랜드는 / 보여지는 방식이 / 다릅니다. | Brands that get chosen / are seen / differently. | 자판 타이핑: `steps()`는 한글이 아니면 글자 하나씩 → 그대로 동작. 줄 나눔·커서 위치만 확인 |
| 포트폴리오 | 실제로 만든 / 웹사이트입니다. | Real websites / we've built. | 로딩 막대를 둘째 줄에 |
| 비교 제목 | 흔한 템플릿 VS 맞춤 디자인 | Template VS Tailored | 그대로 |
| 요금 제목 | 매달 **관리비**는 없게. | No **monthly fees**. | 사선 베기 효과를 'monthly fees'에 |
| 관리비 $0 | 기본 월 **관리비** $0 | Monthly **fee** $0 | 베기 효과를 'fee'에 |

| 제작 과정 | 비전에서 / 현실로 | From vision / to reality. | 외곽선·채움 그대로 |
| AI 영상 샘플 | 평범한 사진 한 장이, / 광고가 됩니다. | One ordinary photo / becomes an ad. | 그대로 |
| 영상 요금 | 기획부터 편집까지, 바로 쓰는 [광고영상]을 드립니다. | From concept to final cut, / a [ready-to-run ad]. | 뷰파인더를 'ready-to-run ad'에 |

| 문의 제목 | 매달 나가는 **웹사이트 관리비,** / 스트레스에서 **해방되세요.** | Those **monthly website fees?** / **Let them go.** | 눌림→튀어 오름을 'monthly website fees?', 빛나며 떠오름을 'Let them go.'에 |

- 글자마다 쪼개는 효과(.burden, .free, .gather, .wy)는 **영어 단어 사이 공백**을 살릴 것(지금은 한국어 기준으로 `--k` 번호를 매김).

## 5. 글꼴 (지금 느낌 그대로, 영어에 맞게)
- **제목(PS Display)**: 이미 영문은 Archivo(좁은 폭 70·굵기 500)라서 영어 제목도 같은 느낌이 난다. 영어는 한국어보다 줄이 길어지므로 **줄을 문구 파일에서 직접 나눠** 지금 높이와 비슷하게 맞춘다.
- **본문(PS Text)**: 지금은 나눔스퀘어 네오의 영문 글자를 쓰는데, 영어 긴 글에서는 어색하다. **영어 페이지 본문은 Archivo 보통 폭(100)·굵기 400/700**으로(같은 Archivo 계열이라 제목과 어울림).
  - `scripts/fonts.py`에 `ps-text-latin`(Archivo 인스턴스, Latin 글자만) 추가, `:lang(en)`에서 본문 글꼴 순서를 바꿈.
- **마무리 선언(PS Letter)**: 지금은 마루 부리에서 한국어 선언 글자만 남긴 4KB 파일이라 영어 글자가 없다. 영어는 **Instrument Serif Italic**(OFL, `drafts/fonts`에 이미 있음)으로 '손편지' 느낌을 유지. fonts.py에서 영어 선언 글자만 남겨 작게.
- 한국어 전용 줄바꿈 규칙(`page.ts`의 `glue()`: 조사·NBSP 처리)은 **한국어 페이지에만** 적용. 영어는 제목 `text-wrap: balance`, 본문 `text-wrap: pretty`.
- `word-break: keep-all`, `word-spacing: .09em`(한글 제목용)은 `:lang(ko)`로 한정.

## 6. 검색·미리보기 (특히 미국)
- `/en`: 영어 제목·설명·키워드, `og:locale en_US`, 영어 `og:title`·`og:description`, 같은 미리보기 이미지(또는 영어 문구판 이미지를 따로 — 사용자 결정).
- 두 페이지 모두 `<link rel="alternate" hreflang="ko" href="https://pause8studio.com/">`, `hreflang="en" href=".../en"`, `x-default` = 한국어.
- 각자 canonical. JSON-LD(회사 정보·FAQ)도 영어판은 영어로.
- `sitemap.xml`에 `/en` 추가(hreflang 표시 포함).
- 한국어 페이지 맨 아래 영어 소개 한 줄은 `/en` 링크로 바꿔 둔다("English version").

## 7. 상담 창·문의 메일
- 상담 창의 모든 문구·오류·완료/실패 화면·메일 앱 본문·복사 문구를 영어로.
- 국가번호 처음 선택: 영어 페이지는 뉴질랜드 접속이면 +64, 그 밖은 +1(한국어와 같은 규칙).
- **받는 메일은 한국어 그대로**(대표님이 읽으므로). 서버는 항목 이름을 한국어로 정리하되:
  - 숨은 칸 `lang=en`을 보내서 메일 제목을 `💻 [PAUSE 상담 · EN] …`로, 맨 위에 "언어: 영어(영어로 답장)" 줄 추가.
  - 상담 종류 값은 영어로 들어오므로 서버에서 한국어로 바꿔 적거나 영어 그대로 둔다(영어 그대로 + 언어 표시면 충분).
- 손님 확인 메일(SMTP를 붙일 때)은 손님 언어로.

## 8. 서버·배포
- `scripts/render.ts`: `index.html`(한국어)과 `en/index.html`(영어)을 같이 만든다. `vite.config.ts`는 입력 두 개(`build.rollupOptions.input`).
- `server.ts`: `/en`·`/en/`·`/en/index.html` → 영어 페이지(통화 표시 넣기 동일). `/en/` → `/en`으로 정리.
- `scripts/vercel.mjs`: 함수 `en` 추가(지금 `index`처럼), 영어 html도 함수 묶음에 복사. **예전 주소를 첫 화면으로 보내는 규칙 `^/(?!api/)[^.]+$`가 `/en`을 잡지 않도록 제외할 것.**
- 미리보기 링크(`scripts/artifact.py`)는 한국어만 유지해도 됨.

## 9. 점검 (구현 후 반드시)
1. `tests/smoke.cjs`를 두 언어로 돌린다(주소 인자). 영어판 추가 검사:
   - 화면·alt·aria·placeholder·JSON-LD에 한글 0자(언어 버튼 제외)
   - 효과 13곳이 영어에서도 시작·끝 모습이 맞는지(지금 검사 항목을 단어만 바꿔 재사용)
   - 언어 버튼: 누르면 `/en#현재섹션`으로, 거기서 다시 `/`로
2. 1440·390 폭, **아이폰 Safari(WebKit)**에서 영어 제목 줄바꿈·잘림 확인(`overflow-clip-margin` 쓰지 말 것 — Safari 미지원, 지금은 clip-path 방식).
3. 접근성 0 위반(axe).
4. 실제 영어 상담 1건을 보내 info@로 오는지(제목 `· EN`).
5. 배포 뒤 실제 사이트에서 `/en`이 열리는지, 스타일 파일 이름이 `dist`와 같은지(배포가 가끔 '권한 없음'으로 조용히 실패함).

## 10. 작업 순서 (Sonnet용)
1. 구조: 문구 타입·`en.ts` 뼈대(일단 한국어 복사) → page.ts가 문구를 인자로 → 두 페이지 생성 → 서버·Vercel 경로 → 언어 버튼. 여기서 한 번 배포해도 됨(영어판 미공개: 버튼 숨김).
2. 스크립트 속 한국어를 문구 파일로 이동.
3. 영어 문구 작성 + 효과 단어 자리(4번 표).
4. 영어 글꼴(5번).
5. 검색·미리보기(6번), 상담 메일(7번).
6. 점검(9번) → 사용자에게 영어 문구 확인 받기 → 버튼 공개 → 배포·푸시.

## 11. 사용자에게 정할 것
1. 영어 버튼 국기: **미국 국기(권장)** / 국기 없이 `EN`만 / 지구 모양
2. 영어 주소: **`pause8studio.com/en`(권장)**
3. 영어 문구 초안(4번 표 포함)은 구현 세션이 전체를 써서 보여 주고 확인받는다. 특히 법적 고지·요금 안내 문구는 직접 확인 필요.
4. 미리보기 이미지: 지금 이미지 그대로 / 영어 문구판 따로
