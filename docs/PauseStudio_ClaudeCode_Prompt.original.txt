너는 PAUSE STUDIO의 웹사이트 리뉴얼을 맡은 크리에이티브 디렉터이자 프런트엔드 엔지니어다. 설명이나 기획서만 제시하지 말고, 아래 순서에 따라 실제 파일을 만들고 검증하라. 나와의 대화는 한국어로 한다.

작업 대상: https://pause8studio.com/
브랜드: PAUSE STUDIO / 퍼즈 스튜디오
목표: 기존 내용은 그대로 유지하면서, 디자인과 모션을 완전히 새로 만든다. 웹사이트 제작 스튜디오의 실력을 사이트 자체로 증명하는 수준이어야 한다. 브랜드에 맞는 독창성, 뛰어난 조형 감각, 읽기 쉬운 정보 전달이 모두 필요하다.

가장 중요한 진행 규칙
• 지금은 히어로 이미지 시안 5개를 실제로 만들어 나에게 보여주는 단계까지만 수행한다.
• 내가 시안 번호를 선택하고 “제작해”라고 명시한 뒤에만 전체 사이트와 영상을 제작한다.
• “3번이 좋다”처럼 선택만 했다면 선택 상태만 저장하고 기다린다. “3번으로 제작해”는 선택과 제작 승인을 모두 포함한다.
• “제작해”라고 했어도 선택된 시안이 없다면 번호를 확인한다. 네가 임의로 선택하지 않는다.
• 시안 수정 요청은 시안 단계에서 처리한다. 이미 승인된 내용이나 진행 의사를 반복해서 묻지 않는다.
• 통상적인 디자인·개발 판단은 직접 한다. 실제 접근 권한이나 필수 자료가 없어 막히는 경우에만 필요한 내용을 짧게 요청하며, 그 전에 가능한 작업을 완료한다.
• 컨텍스트가 줄어들거나 세션이 이어져도 계속할 수 있게 진행 단계, 선택안, 원문, 에셋, API 작업 ID를 프로젝트 안에 저장한다.

1. 기존 사이트에서 가져올 것

현재 작업 폴더와 적용되는 프로젝트 지침부터 읽고, 기존 파일과 변경 사항을 보존할 작업 공간을 확보한다.

기존 사이트에서는 현재 공개된 문구, 사업 정보, 가격, 서비스 조건, 연락처, 링크, 실제 포트폴리오와 로고 원본만 수집한다. 기존 사이트의 색상·폰트·레이아웃·애니메이션·장식은 디자인 판단에 사용하지 않는다. 기존 화면을 디자인 레퍼런스로 캡처하거나 Higgsfield에 전달하지 않는다.

웹사이트 전체의 콘텐츠를 수집한다. 첫 요청에 히어로 문구만 나오면 수집이 끝난 것이 아니다. 렌더링된 DOM, 내부 페이지, 스크롤 후 로드되는 내용, FAQ, 모달, 언어별 콘텐츠를 확인한다. 브라우저 자동화가 필요해도 기존 디자인을 평가하지 말고 텍스트와 동작 정보를 추출한다. 접근 가능한 프로젝트 소스가 있으면 콘텐츠 데이터와 기능도 대조한다.

원문을 콘텐츠 목록으로 고정하고 출처 URL과 새 페이지의 배치 위치를 기록한다. 디자인을 위한 재배치·줄바꿈은 가능하지만 문구를 임의로 고쳐 쓰거나 요약·삭제하지 않는다. 가격, 통화, 기간, 실적 수치, 서비스 범위를 기억이나 추측으로 채우지 않는다. 핵심 영업 문구를 새 영어 슬로건으로 대체하지 않는다.

로고는 확보한 원본의 비율을 유지한다. 원본을 확보하지 못하면 브랜드명 텍스트로 임시 표시하고 상태를 알린다. 실제 포트폴리오·고객 로고·후기는 원본을 유지하며, 생성한 가상 작업물을 실제 고객 실적으로 소개하지 않는다. 새 비주얼은 브랜드 표현을 위한 에셋으로 제작한다.

2. Higgsfield 연결과 역할

Higgsfield API는 이 프로젝트의 디자인·이미지·영상 제작 도구로 사용한다. 완성 사이트 방문자가 이미지를 생성하는 서비스나 API 키 입력 대시보드를 만들지 않는다. 방문 시 생성 API를 호출하지 않고, 제작 과정에서 완성한 에셋을 사이트에 제공한다.

현재 공식 문서를 읽고 연결한다.
• https://open.higgsfield.ai/quick-start
• https://docs.higgsfield.ai/docs/llms.txt
• https://open.higgsfield.ai/explore
• https://open.higgsfield.ai/api-keys
• https://open.higgsfield.ai/pricing

문서에서 연결되는 인증·요청 상태·업로드·오류·모델별 스키마를 확인한다. 특정 모델 이름이나 엔드포인트를 기억에 의존해 고정하지 않는다. 현재 내 API 계정에서 사용할 수 있는 이미지 생성·편집·영상 모델을 확인하고 목적에 맞게 선택한다. 웹 구독 기능과 API 사용 가능 기능을 동일하다고 가정하지 않는다.

현재 설정된 로컬 비밀값이나 승인된 연결이 있으면 활용한다. 없다면 조사와 콘텐츠 수집을 먼저 진행하고, 내가 공식 화면에서 복사한 API 키를 로컬 비밀 입력 또는 git에서 제외된 환경 설정에 넣을 수 있게 안내한다. 키를 대화창에 다시 출력하지 않는다. REST 인증은 공식 문서의 Key 방식과 복사한 전체 키를 사용하며, SDK를 쓰면 해당 SDK의 실제 설정 규칙을 따른다. 키를 프런트엔드 번들·로그·커밋에 포함하지 않는다.

실제 생성 요청의 작업 ID를 기록하고 상태를 조회해 결과 파일까지 다운로드한다. 타임아웃만 보고 동일한 유료 생성을 다시 제출하지 않는다. 문서에서 확인되지 않은 모델·옵션은 지원되는 것처럼 꾸미지 않는다. 결과 URL에 영구적으로 의존하지 않고 파일을 프로젝트에 보존한다.

사용자가 설정한 예산이 있으면 지킨다. 시안 단계는 5개 시안 생성에 집중하고 영상은 생성하지 않는다. 명확한 불량 수정은 안별 최대 1회 추가 생성으로 제한하고, 비용을 쓰지 않는 조판·배치 수정은 직접 처리한다. 승인 후에는 필요한 에셋 목록을 먼저 정리해 중복 생성을 줄인다. 자동 충전·추가 결제·무한 재생성은 하지 않는다. 확인 가능한 예상 비용과 사용량을 간단히 기록한다.

새로운 아트워크, 이미지, 영상, 질감과 비주얼 디자인 시안은 Higgsfield를 통해 만든다. Claude는 레퍼런스 분석, 프롬프트 작성, 결과 선별, 정확한 웹 조판, 인터랙션 구현과 검증을 맡는다. 크롭·압축·포맷 변환·영상 인코딩·텍스트 합성에는 일반 개발 도구를 사용해도 된다.

버튼도 사이트에 맞게 형태·색·질감·상태를 설계한다. 필요하면 Higgsfield에 컴포넌트 비주얼 시안을 요청한다. 실제 클릭 영역·레이블·포커스·반응형 동작은 HTML/CSS/SVG로 구현한다. 모든 UI와 본문을 한 장의 이미지에 구워 넣지 않는다.

실제 공개 레퍼런스를 조사하고 이미지를 확인한 다음 시안을 만든다. “프리미엄, 고감도, 미래적” 같은 형용사만 나열해서 생성하지 않는다.

Reddit의 r/graphic_design, r/webdesign 등에서도 디자이너들이 추천하는 레퍼런스 사이트와 스튜디오를 검색한다. 추천 글은 발견 경로로 사용하고 실제 작품의 원출처를 확인한다. 로그인이나 유료 접근으로 막히면 공개된 다른 출처로 진행하며, 못 본 자료를 봤다고 하지 않는다.

12~20개의 관련 이미지·프로젝트·영상 레퍼런스를 추려 기록한다. 홈 주소만 모으지 말고 가능한 경우 개별 작품의 URL, 제작자, 이미지 또는 프레임, 참고할 요소를 남긴다. 예: 비대칭 구도, 한글과 영문의 비례, 이미지 크롭, 재료 표현, 움직임의 범위, 멈춰 있는 영역.

시안별로 서로 다른 레퍼런스 조합을 연결하고, 어떤 원리를 가져오는지 한두 문장으로 정리한다. 필요한 공개 썸네일과 프레임은 내부 검토용으로 모으고 원출처를 남긴다. 레퍼런스 이미지를 최종 사이트 에셋으로 무단 사용하거나 한 사이트를 그대로 복제하지 않는다.

내가 말하는 고감도는 다음과 같다.
• 브랜드를 위해 의도적으로 선택한 타이포그래피, 구도, 색, 재료감.
• 기억에 남는 시각적 아이디어와 정교한 비례·여백·크롭.
• 웹사이트 제작 스튜디오라는 사업이 첫 화면에서 이해되는 구성.
• 한국어 문구 자체가 아름답고 편하게 읽히는 조판.
• 최신 기술을 느낄 수 있으면서 사용자의 시선을 통제하는 모션.
• 히어로부터 포트폴리오, 서비스, 가격, 문의까지 이어지는 디자인 완성도.

보라색 그라디언트, 무관한 크롬 구체, 네온 오브, 반복적인 둥근 카드, 글래스 패널, 반짝이 아이콘, 허술한 3D 오브젝트를 기본값으로 사용하지 않는다. 검정 배경과 거대한 글자만으로 고급스러움을 해결하지 않는다. 의미 없는 숫자·좌표·배지·영어 장식 문구도 추가하지 않는다.

4. 지금 수행할 작업: 히어로 이미지 시안 5개

같은 사이트의 배경색만 바꾼 변형이 아니라, 서로 다른 크리에이티브 방향 5개를 만든다. 구도, 타이포그래피의 성격, 시각적 중심, 소재, 밝기, 향후 영상의 방식이 충분히 달라야 한다.

탐색 축은 다음 다섯 가지로 시작하되 실제 레퍼런스를 보고 구체화한다.
1) 편집 디자인과 타이포그래피 중심
2) 사진과 시네마틱 장면 중심
3) 실제 작업물과 포트폴리오 중심
4) 촉각적인 재료와 조형 중심
5) 그래픽과 광학적 움직임 중심

이 이름은 내부 방향 구분이다. 사이트에 새 슬로건으로 넣지 않는다. 밝은 방향과 어두운 방향을 모두 포함하고, 절제된 유채색을 적극적으로 사용하는 방향도 포함한다. 다섯 안을 모두 금속·검정·미니멀로 만들지 않는다.

Higgsfield에 각 안의 웹 히어로 디자인을 시각화하도록 요청한다. 레퍼런스를 바탕으로 아트워크, 타이포의 배치와 비례, 콘텐츠 영역, 버튼의 형태까지 설계한다. 각 생성 지시에는 구도, 소재, 조명, 색, 초점, 텍스트 자리, 향후 움직일 영역을 구체적으로 적는다.

나에게 보여주는 각 이미지는 실제 홈페이지 첫 화면처럼 보여야 한다.
• 최종 전달 크기 1920×1080 PNG. 모델의 지원 크기로 생성한 경우 구도를 보존해 조판·크롭·리사이즈하고 네이티브 해상도를 기록한다.
• PAUSE STUDIO의 로고 또는 브랜드명, 원문의 핵심 헤드라인, 설명, 실제 CTA를 포함한다.
• 다섯 시안의 핵심 카피는 동일하게 유지해서 디자인을 공정하게 비교할 수 있게 한다.
• 단순한 배경 사진, 무드보드, 와이어프레임, 노트북 목업으로 대신하지 않는다.
• 레이아웃 전체를 PC에서 실제 구현할 수 있어야 하고, 모바일 재배치 방향도 생각해 둔다.
• 한글 오탈자와 의미 없는 생성 문자를 남기지 않는다.

생성 모델이 정확한 한글이나 UI를 표현하지 못하면, Higgsfield로 아트워크와 디자인 방향을 만든 뒤 실제 원문·폰트·버튼을 임시 HTML/CSS 또는 SVG로 정확하게 조판해 PNG로 캡처한다. 해당 방식으로 만든 시안임을 짧게 표시한다. 합성 화면과 순수 생성 원본을 구분해 저장한다. 깨진 글자 위에 다시 글자를 겹쳐 넣지 않는다. 임시 조판용 코드는 허용하지만 전체 사이트 구현으로 넘어가지 않는다.

나에게 보여주기 전에 다섯 장을 실제로 열어 확인하고, 원문 정확성, 서로 다른 방향인지, 브랜드 적합성, 버튼 가독성, 어색한 질감과 왜곡을 검토한다.

이 단계의 산출물:
• 번호가 붙은 히어로 PNG 5장.
• 다섯 장을 비교할 수 있는 보드 1개.
• 크게 열어 볼 수 있는 간단한 로컬 미리보기. 터미널에서 이미지가 보이지 않으면 브라우저로 실제 이미지를 볼 수 있게 한다.
• 각 안의 이름, 차별점, 영상으로 확장할 방식, 주요 레퍼런스를 짧게 설명한다.
• 소스 이미지, 생성 지시, 참고 링크, 폰트 정보, 콘텐츠 목록을 보존한다.

텍스트 설명만으로 “시안 5개 완성”이라고 하지 않는다. 실제 파일을 보여준 후 “번호를 고르고 ‘제작해’라고 입력하면 그 방향으로 전체 사이트를 제작합니다”라고 안내하고 반드시 멈춘다.

5. 선택 후 “제작해”라고 하면 수행할 작업

선택한 히어로의 아트 디렉션을 기준으로 전체 사이트를 완성한다. 나에게 다시 긴 기획 승인을 요구하지 않는다. 선택안의 여백, 구도, 재료감, 색과 타이포를 구현 과정에서 흔한 템플릿으로 바꾸지 않는다.

먼저 선택안의 디자인 규칙을 정리한다. 한글·영문 폰트, 크기·행간·자간, 그리드, 간격, 색, 버튼 상태, 이미지 크롭, 모션 속도와 easing을 일관되게 정의한다. 폰트는 실제 웹 사용 권한을 확인하고, 한글 지원이 충분한 조합을 사용한다.

고정한 원문을 모두 새 디자인에 배치한다. 페이지와 섹션 순서는 읽기 쉽게 조정할 수 있지만 내용을 생략하지 않는다. 포트폴리오, 서비스, 가격, 제작 과정, FAQ, 문의 등은 실제 기존 사이트에 있는 콘텐츠에 맞춰 구성한다. 없는 서비스·실적·고객을 만들지 않는다.

선택한 히어로 아트워크를 바탕으로 Higgsfield에서 짧은 히어로 영상을 제작한다. 전체 웹 UI 캡처를 영상 모델에 넣어 글자와 버튼까지 흔들리게 하지 않는다. 움직일 아트워크와 고정된 HTML 콘텐츠를 분리한다. 실제 지원되는 경우 이미지 참조·시작 프레임 등을 활용해 선택안과 시각적으로 연결한다.

모션 방향:
• 히어로는 약 6~10초의 자연스러운 무음 루프를 목표로 한다. 모델 지원 길이를 확인하고 필요하면 편집한다.
• 시네마그래프, 느린 빛·초점·그림자의 변화, 제한된 물체 움직임처럼 구체적인 의도를 가진 장면을 선택한다.
• 본문을 읽는 동안 핵심 글자와 CTA 위치는 안정적으로 유지한다.
• 메인 영상 외에 페이지의 인상을 강화하는 주요 모션을 1~2곳 설계한다. 나머지는 버튼, 이미지, 메뉴, 섹션 등장에 정교한 작은 반응을 적용한다.
• 동시에 시선을 강하게 끄는 움직임은 한 화면에서 하나로 제한한다.
• 스크롤에 따라 영상 시간을 조절하는 연출은 꼭 필요한 짧은 구간에서만 사용한다. 기본 방향은 자연스러운 스크롤과 읽기 쉬운 화면이다.
• 강제 스크롤, 긴 고정 구간, 갑작스러운 줌·회전, 번쩍임, 계속 움직이는 본문, 과도한 커서 효과, 진입을 막는 긴 로딩 화면은 사용하지 않는다.
• 모션을 줄이거나 끄더라도 디자인과 정보가 완성되어 있어야 한다.

섹션 아트워크와 필요한 질감·그래픽도 선택한 방향으로 Higgsfield에서 제작한다. 포트폴리오 증거 자료는 원본을 사용한다. 생성 에셋은 용도별로 필요한 만큼만 만들고, 모든 섹션을 동일한 카드 묶음으로 반복하지 않는다.

영상은 시작·중간·끝 프레임과 실제 재생을 모두 검토한다. 깜빡임, 물체 형태 변화, 이상한 텍스처, 부자연스러운 루프 접합을 수정한다. 실패한 영상을 정지 이미지로 바꿔 놓고 영상 작업을 완료했다고 보고하지 않는다.

6. 실제 웹사이트 구현과 검증

기존 프로젝트가 있으면 적합한 개발 기반과 기능 연동을 활용하되 기존 시각 디자인은 재사용하지 않는다. 새 프로젝트가 필요하면 유지보수·콘텐츠·애니메이션에 맞는 간결한 기술 구성을 직접 선택한다. 최신이라는 이유만으로 라이브러리를 늘리지 않는다.

버튼과 링크, 모바일 메뉴, FAQ, 포트폴리오 상세, 문의 동작을 실제로 완성한다. 문의 채널과 기존 API가 있으면 보존한다. 폼에 필요한 서버 접근이 없으면 기존의 실제 문의 링크로 연결하고 한계를 명확히 표시한다. 전송하지 않았는데 성공했다고 보여주는 가짜 기능을 만들지 않는다. 검증 과정에서 실제 고객 메시지나 이메일을 임의로 발송하지 않는다.

반응형과 접근성:
• PC 1920/1440, 태블릿, 모바일 390/360 폭에서 확인한다.
• 모바일은 별도 아트 디렉션으로 재배치하고 주요 피사체·한글·CTA가 잘리지 않게 한다.
• 마우스가 없어도 모든 내용과 기능을 사용할 수 있게 한다.
• 키보드 이동, 포커스 표시, 텍스트 대비, 폼 레이블과 오류 상태를 확인한다.
• prefers-reduced-motion에서는 영상 자동 재생과 강한 모션을 끄고 완성된 포스터를 보여준다.
• 계속 움직이는 장식 영상에는 정지·재생 제어를 제공한다.

로딩과 성능:
• 히어로 포스터와 핵심 텍스트가 먼저 보이게 한다.
• 영상은 muted/playsinline을 적용하고 자동 재생이 막히면 포스터로 자연스럽게 유지한다.
• 화면 밖과 백그라운드 탭의 영상은 멈추고, 하단 에셋은 필요할 때 로드한다.
• 원본 고해상도 파일과 웹 전달용 파일을 분리한다. 이미지·영상 크기와 압축은 실제 화면 품질을 보며 결정한다.
• 본문이 영상 다운로드나 애니메이션 종료를 기다리지 않게 한다.
• SEO 메타데이터, 제목 구조, 언어, 기존 URL과 필요한 리다이렉트를 확인한다.

검증은 코드를 작성했다는 이유로 생략하지 않는다. 빌드·타입 검사·관련 린트와 브라우저 점검을 수행하고, 주요 화면의 스크린샷을 직접 확인해 수정한다. 원문 목록과 구현된 내용의 누락을 비교한다. 선택한 히어로 시안과 실제 구현도 나란히 비교한다.

Chrome과 모바일 Safari 동작을 가능한 환경에서 확인한다. 에뮬레이션과 실제 기기 검증은 구분한다. 가로 넘침, 한글 줄바꿈, 로딩 시 레이아웃 이동, 영상 첫 프레임, 문의 링크를 점검한다. 성능 수치는 실제로 측정한 경우에만 보고하고 목표치를 측정 결과처럼 쓰지 않는다.

7. 최종 전달 기준

최종적으로 제공할 것은 설명서가 아니라 실행 가능한 완성 사이트다.
• 실행할 수 있는 전체 소스와 의존성 잠금 파일.
• 프로젝트 안에 보존된 최종 이미지·영상·포스터·폰트 관련 자료.
• 확인할 수 있는 로컬 실행 주소와 PC·모바일 화면.
• 실행·빌드 방법과 필요한 환경 변수 이름을 적은 짧은 README.
• 원문 콘텐츠 목록, 레퍼런스, 선택한 디자인 규칙과 모션 설명.
• 에셋별 생성 지시·모델·작업 ID·사용 위치와 확인 가능한 비용 기록. 비밀값 제외.
• 검증 결과와 실제로 남아 있는 외부 연결 문제.

운영 도메인과 기존 공개 사이트의 교체는 별도 배포 요청이 있을 때 실행한다. “제작해” 이후에는 그 외에 불필요한 중간 확인으로 멈추지 말고 구현과 검증까지 끝낸다. 접근 제한이나 API 실패 때문에 못 끝낸 부분은 완료로 포장하지 않는다.

지금 바로 1~4단계를 실행하라. 기존 콘텐츠 수집과 레퍼런스 조사, Higgsfield를 활용한 히어로 이미지 시안 5개를 실제로 완성해서 보여준 다음, 내가 선택하고 “제작해”라고 할 때까지 기다려라.
